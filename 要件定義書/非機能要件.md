# ユーザビリティおよびアクセシビリティ：システムは誰がどのように使う？
- 不特定多数の利用者がAPIクライアント経由で使用する
- 現時点ではAPIとして提供し、Webフロントエンドは将来対応


# システム方式：システムの構成は？
- バックエンド：FastAPI（Python）
- データベース：PostgreSQL（本番）/ SQLite（開発）
- 認証：JWT（JSON Web Token）
- コンテナ：Docker
- クラウド：AWS


# 規模：想定される同時ユーザー数やトランザクション数は？
- 同時利用者数：最大10人


# 性能：応答時間や処理速度、閾値（しきい値）は？
- APIレスポンスタイム：5秒以内


# 信頼性：稼働率の目標、バックアップ間隔、復旧時間の目安は？
- 稼働率：目標なし（オンデマンド起動のため常時稼働を前提としない）
- バックアップ：必要（間隔・方式は運用時に定める）


# 拡張性：将来的なユーザー数やデータ量の増加に対応するための設計方針は？
- Dockerによりスケールアップ・スケールアウトに対応可能な構成とする
- 将来的にWebフロントエンドを追加できる構成とする


# 互換性：新旧システム間でのデータの互換性は？
- 対象なし（新規開発のため）


# 継続性：システムの冗長性・耐障害性を高めるための方策は？
- 現時点では対象なし（小規模・オンデマンド運用のため）


# セキュリティ：必要とされるセキュリティレベルは？
- パスワードのハッシュ化：Argon2
- 認証：JWTトークン
- 通信：HTTPS


# 稼働環境：セキュリティを考慮した最適な稼働環境は？
- AWS上でDockerコンテナとして稼働
- オンデマンド起動（使用時のみサーバーを起動）


# テスト：システムの品質を確保するために必要なテストの種類・方法は？
- 単体テスト：各APIエンドポイントの動作確認
- 結合テスト：認証・DB操作を含む一連のフロー確認


# 移行：移行のプロセスやスケジュールは？
- 対象なし（新規開発のため）


# 引継ぎ：引継ぎ範囲や対象者、方法は？
- 対象なし（1人で運用・保守）


# 教育：運用方法・利用方法の教育について
- 対象なし


# 運用：運用体制・運用業務について
- 運用担当：1人
- オンデマンド起動による運用
- バックアップの定期実施


# 保守：保守体制について
- 保守担当：1人
- 不具合発生時に随時対応
