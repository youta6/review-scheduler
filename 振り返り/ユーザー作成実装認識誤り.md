## 認識誤り：登録ユーザー数上限チェックを try ブロック内に含めていた

### 発生した問題

`create_user_endpoint` において、登録ユーザー数上限チェック（ユーザー数 >= 99 の場合に `HTTPException(status_code=409, detail="登録可能ユーザーが上限に達しました。")` を raise する処理）が try ブロック内に含まれていた。

`HTTPException` は `Exception` のサブクラスであるため、直後の `except Exception` 節に捕捉され、「入力したユーザー名は既に登録されています」というユーザー名重複を示すメッセージに上書きされていた。結果として、登録数が上限に達した場合でも正しいエラーメッセージが返却されない状態だった。

```python
# 修正前：上限チェックが try 内にあり HTTPException が捕捉される
try:
    all_users = get_users(db)
    if len(all_users) >= 99:
        raise HTTPException(...)   # ← except Exception に捕捉されてしまう
    ...
except Exception:
    raise HTTPException(status_code=409, detail="入力したユーザー名は既に登録されています")

# 修正後：上限チェックを try の外に移動
all_users = get_users(db)
if len(all_users) >= 99:
    raise HTTPException(...)       # ← そのまま伝播する

try:
    ...
except Exception:
    raise HTTPException(status_code=409, detail="入力したユーザー名は既に登録されています")
```

### 本来どの工程で発見すべきだったか

**実装時**（コードレビュー時）に発見すべきだった。

`except Exception` は Python の全例外（`HTTPException` を含む）を捕捉するため、try ブロック内で `HTTPException` を raise する処理を書く場合は意図しない捕捉が起きないか確認する必要がある。

### 見落とした理由

`except Exception` を「DB 操作の例外をまとめて処理する」という認識で記述しており、try ブロック内に含まれる `HTTPException` も捕捉対象になることを見落とした。上限チェックと DB 書き込みを同一の try ブロックにまとめた結果、責務の境界が曖昧になっていた。

### 教訓

- `except Exception` を使う場合、try ブロック内で `HTTPException` を raise していないか必ず確認する
- try ブロックの範囲は「捕捉したい例外が発生しうる処理のみ」に限定する。上限チェックのような前処理は try の外に置く
- 捕捉したい例外が特定できる場合（`IntegrityError` など）は `except Exception` より具体的な例外クラスを指定する
