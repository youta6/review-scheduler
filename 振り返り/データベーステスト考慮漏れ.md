## 考慮漏れ：`declarative_base` の import 元が非推奨モジュール

### 発生した問題

`database.py:2` にて、`declarative_base` を非推奨の `sqlalchemy.ext.declarative` から import していた。

```python
# database.py:2（修正前）
from sqlalchemy.ext.declarative import declarative_base  # 非推奨

# 修正後
from sqlalchemy.orm import declarative_base  # 推奨
```

SQLAlchemy の更新により `sqlalchemy.ext.declarative` の `declarative_base` は非推奨となっており、`sqlalchemy.orm` の `declarative_base` を使用することが推奨されている。

### 本来どの工程で発見すべきだったか

**実装工程のコードレビュー**で発見すべきだった。

ライブラリのバージョンと推奨 API を確認するレビューを行っていれば、import 元が非推奨となっていることに気づけた。単体テスト工程でコードを精査した際に発覚した。

### 見落とした理由

`sqlalchemy.ext.declarative` の `declarative_base` は動作するため（非推奨ではあるがエラーにはならない）、実装・レビュー時に問題として認識されなかった。使用ライブラリの API 変更点や非推奨化の確認が実装・レビュープロセスに組み込まれていなかった。

### 教訓

外部ライブラリの import は、使用しているバージョンにおいて推奨されている import パスを使っているかをレビューで確認する。特に SQLAlchemy のような頻繁にアップデートされるライブラリは、リリースノートの非推奨情報を参照する。
