## 考慮漏れ：設計書の全異常系分岐を網羅できていなかった

### 発生した問題

以下の2つのテストケースが未作成だった。

| 項番 | 漏れていたケース | 設計書の根拠 |
|---|---|---|
| No.5 | password なし → HTTP 422 | 引数定義：password は必須（Pydantic バリデーション） |
| No.6 | 登録数99件以上 → HTTP 409 | 処理概要 2.(2)：登録ユーザー数上限チェック |

### 本来どの工程で発見すべきだったか

**テスト仕様書作成時**に発見すべきだった。

設計書の「引数定義（必須項目）」と「処理概要（例外処理）」を上から順に確認しながらテストケースを作成していれば、両方とも作成時点で網羅できた。

### 見落とした理由

ユーザー名重複（HTTP 409）のみに着目し、同じエンドポイントに存在する別の HTTP 409（登録数上限）を見落とした。また、必須パラメータの欠落ケースは user_name のみ意識しており、password についての確認が不足していた。

### 教訓

テストケース設計時は、設計書の以下を漏れなく確認する。
- **引数定義の必須項目**：各必須パラメータを1つずつ欠落させた異常系ケースを用意する
- **処理概要の例外処理テーブル**：同一ステータスコード（409など）が複数条件で発生し得る場合、それぞれを個別のテストケースとして作成する
