## 設計漏れ：HTTP 422 が設計書に記載されていなかった

### 発生した問題

POST /users の設計書（ユーザー作成_v1.0.md）に、異常系レスポンスとして HTTP 422 Unprocessable Entity の記載がなかった。必須パラメータ（user_name または password）が欠落した場合、FastAPI/Pydantic が自動的に HTTP 422 を返却するが、API 利用者が設計書からその挙動を把握できない状態になっていた。

### 本来どの工程で発見すべきだったか

**設計書作成時**に発見すべきだった。

FastAPI は Pydantic モデルを使ったリクエストバリデーションを自動で行い、必須パラメータが欠落していると HTTP 422 を返却する。これはフレームワークの仕様として既知の挙動であり、引数定義を記述する時点で同時に記載できた。

### 見落とした理由

設計書の異常系として意識していたのは、実装で明示的に `raise HTTPException(...)` を記述する箇所（ユーザー名重複・登録数上限）のみだった。FastAPI/Pydantic が自動で返却するレスポンスについては「実装しなくても動く」という認識から記載対象として考慮していなかった。

### 教訓

- FastAPI エンドポイントの設計書には、明示的に実装した例外だけでなく **フレームワークが自動返却するレスポンス**（HTTP 422 など）も記載する
- 引数定義に必須パラメータを記載する際は、セットでバリデーションエラー時のレスポンスも記載する習慣をつける
