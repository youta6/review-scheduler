## 認識誤り：POST /token が本番環境で到達不能だった

### 発生した問題

結合テスト自動化（TestClient）で POST /token を呼び出したところ HTTP 404 が返却された。

調査の結果、`auth.py` 内で `app = FastAPI()` という独立した FastAPI インスタンスを作成し、そこに `/token` ルートを登録していたことが判明した。`main.py` は別の `app = FastAPI()` を持ち、`fastapi run app/main.py` で起動するのは `main.py` の `app` のみであるため、`auth.py` 側の `/token` ルートは本番環境でも到達不能な状態だった。

```python
# 修正前：auth.py が独立した FastAPI インスタンスを持ち、main.py から到達できない
# auth.py
app = FastAPI()

@app.post("/token")       # main.py の app には登録されていない
async def generate_token(...):
    ...

# 修正後：APIRouter を使って main.py に統合する
# auth.py
router = APIRouter()

@router.post("/token")
async def generate_token(...):
    ...

# main.py
from app.auth import get_current_active_user, router as auth_router

app = FastAPI()
app.include_router(auth_router)   # /token が main.py の app に登録される
```

### 本来どの工程で発見すべきだったか

**実装時**（コードレビュー時）に発見すべきだった。

FastAPI では、ルートを別モジュールに分割する場合は `APIRouter` を使い、メインの `app` に `include_router` で統合するのが推奨パターンである。複数の `FastAPI()` インスタンスにルートを分散させても、起動に使われる `app` 以外のルートは外部から到達できない。

### 見落とした理由

`auth.py` に独自の `app = FastAPI()` を作成しルートを登録した際、`main.py` への統合が必要であるという認識がなかった。`get_current_active_user` を `main.py` から import して使えていたため、`auth.py` が main.py に組み込まれていると誤認していた可能性がある。

### 教訓

- FastAPI でルートを複数ファイルに分割する場合は `APIRouter` を使い、必ず `app.include_router()` でメインの `app` に登録する
- 関数の import と ルートの登録は別物。関数を import できても、そのルートが `app` に登録されているとは限らない
- 実装後に全エンドポイントが `app.routes` に含まれているか確認する習慣をつける
