# 復習項目削除 結合テスト — 考慮漏れと対応記録

作成日：2026/6/20

対象テスト仕様書：`テスト仕様書/結合テスト仕様書/復習項目操作/復習項目削除_結合テスト仕様書.md`

参照指摘表：
- `レビュー指摘表/結合テスト工程/テスト仕様書レビュー/復習項目操作/復習項目削除_v0.1_レビュー指摘表.md`（No.1、No.4）

---

## 考慮漏れ（1）：必須パラメータ欠落（review_id なし）のテストケースが未作成

### 発生した問題

リクエストボディが空（`{}`）で必須パラメータ `review_id` 自体が存在しない場合の HTTP 422 テストケースが未作成だった。

### 本来どの工程で発見すべきだったか

**テスト仕様書作成時**に発見すべきだった。

引数定義で `review_id` が必須と明記されており、確認していれば作成時点で網羅できた。

### 見落とした理由

正常系（review_id 指定あり）と存在しない review_id の異常系には着目できていたが、「パラメータ自体が存在しない」バリデーション異常系を独立した観点として意識できなかった。

### 教訓

リクエストボディを持つエンドポイントでは、各必須パラメータを欠落させた HTTP 422 ケースをテスト仕様書に必ず含める。

## 考慮漏れ（2）：削除済みユーザーによるアクセスのテストケースが未作成

### 発生した問題

参照指摘表：`レビュー指摘表/結合テスト工程/テスト仕様書レビュー/復習項目操作/復習項目削除_v0.1_レビュー指摘表.md`（No.2）

JWT トークン取得後にユーザーが削除された場合（delete_flag=true）に HTTP 403 が返ることを確認するテストケース（No.4）が未作成だった。

### 本来どの工程で発見すべきだったか

**テスト仕様書作成時**に発見すべきだった。

認証・認可が必要なエンドポイントにはユーザー存在チェック（有効ユーザー検証）が含まれており、この観点を確認していれば作成時点で網羅できた。

### 見落とした理由

復習項目の削除という操作に着目してテストケースを設計しており、認証処理内のユーザー存在チェックという観点が抜けていた。「トークンが有効＝ユーザーも有効」と誤って前提を置いていた。

### 教訓

認証・認可が必要なエンドポイントのテストケースには、以下を独立した異常系として含める。
- トークンなし → HTTP 401
- 削除済みユーザーのトークン → HTTP 403（ユーザー存在チェック失敗）

## 考慮漏れ（3）：URLパスのパラメータが無視される実装挙動の確認テストが未作成

### 発生した問題

参照指摘表：`レビュー指摘表/結合テスト工程/テスト仕様書レビュー/復習項目操作/復習項目削除_v0.1_レビュー指摘表.md`（No.3）

エンドポイント関数の引数に `{user_id}` と `{review_id}` が宣言されておらず、URLパスのパラメータは実装上無視される。URLの `review_id` とボディの `review_id` が異なる場合にボディの値が優先されることを確認するテストケース（No.5）が未作成だった。

### 本来どの工程で発見すべきだったか

**テスト仕様書作成時**に発見すべきだった。

実装コードを確認すればエンドポイント関数の引数定義でURLパスのパラメータが宣言されていないことが分かり、この挙動を確認するテストケースを作成できた。

### 見落とした理由

テスト仕様書を設計書のエンドポイント仕様のみを参照して作成しており、実装コードの引数定義まで確認できていなかった。URLパスのパラメータが実際に使われているかどうかを検証する観点が欠けていた。

### 教訓

URLパスにパラメータを持つエンドポイントでは、実装コードの引数定義を確認し、パスパラメータが実際に使用されているかを検証するテストケースを含める。パスパラメータとボディパラメータが同名の場合は特に、どちらが優先されるかを明示的に確認する。

## 考慮漏れ（4）：削除済みユーザーアクセス時のエラーメッセージを誤認識

### 発生した問題

参照指摘表：`レビュー指摘表/結合テスト工程/テスト仕様書レビュー/復習項目操作/復習項目削除_v0.1_レビュー指摘表.md`（No.4）

テスト仕様書 No.4（削除済みユーザーによるアクセス）の想定結果に `{"detail": "権限がありません"}` と記載したが、実装コード（main.py 537 行目）の正しいメッセージは `{"detail": "削除済みユーザーのため更新できません"}` だった。

### 本来どの工程で発見すべきだったか

**テスト仕様書作成時**に発見すべきだった。

実装コードの `raise HTTPException(...)` の `detail=` 引数を参照すれば正しいメッセージを確認できた。

### 見落とした理由

エラーメッセージを実装コードで確認せず、一般的な表現（`"権限がありません"`）を推測で記載してしまった。

### 教訓

異常系テストケースの想定結果に含まれるエラーメッセージは、必ず実装コードの `raise HTTPException(...)` の `detail=` 引数を確認して転記する。推測で記載しない。
