## 考慮漏れ（1）：必須パラメータ欠落（review_id なし）のテストケースが未作成

### 発生した問題

リクエストボディが空（`{}`）で必須パラメータ `review_id` 自体が存在しない場合の HTTP 422 テストケースが未作成だった。

### 本来どの工程で発見すべきだったか

**テスト仕様書作成時**に発見すべきだった。

引数定義で `review_id` が必須と明記されており、確認していれば作成時点で網羅できた。

### 見落とした理由

正常系（review_id 指定あり）と存在しない review_id の異常系には着目できていたが、「パラメータ自体が存在しない」バリデーション異常系を独立した観点として意識できなかった。

### 教訓

リクエストボディを持つエンドポイントでは、各必須パラメータを欠落させた HTTP 422 ケースをテスト仕様書に必ず含める。

## 考慮漏れ（2）：削除済みユーザーによるアクセスのテストケースが未作成

### 発生した問題

参照指摘表：`レビュー指摘表/結合テスト工程/テスト仕様書レビュー/復習項目操作/復習項目削除_v0.1_レビュー指摘表.md`（No.2）

JWT トークン取得後にユーザーが削除された場合（delete_flag=true）に HTTP 403 が返ることを確認するテストケース（No.4）が未作成だった。

### 本来どの工程で発見すべきだったか

**テスト仕様書作成時**に発見すべきだった。

認証・認可が必要なエンドポイントにはユーザー存在チェック（有効ユーザー検証）が含まれており、この観点を確認していれば作成時点で網羅できた。

### 見落とした理由

復習項目の削除という操作に着目してテストケースを設計しており、認証処理内のユーザー存在チェックという観点が抜けていた。「トークンが有効＝ユーザーも有効」と誤って前提を置いていた。

### 教訓

認証・認可が必要なエンドポイントのテストケースには、以下を独立した異常系として含める。
- トークンなし → HTTP 401
- 削除済みユーザーのトークン → HTTP 403（ユーザー存在チェック失敗）
