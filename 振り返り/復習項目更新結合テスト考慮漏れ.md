## 考慮漏れ：必須パラメータ欠落（review_id なし）のテストケースが未作成

### 発生した問題

リクエストボディが空（`{}`）で必須パラメータ `review_id` 自体が存在しない場合の HTTP 422 テストケースが未作成だった。

既存の No.4「全更新項目未入力」は `{"review_id": 1}` を含むケース（任意フィールドがすべて未指定）であり、`review_id` 自体の欠落ケースとは別の分岐。

### 本来どの工程で発見すべきだったか

**テスト仕様書作成時**に発見すべきだった。

引数定義で `review_id` が必須（`ge=1, le=99`）と明記されており、確認していれば作成時点で網羅できた。

### 見落とした理由

「入力未設定」を No.4（任意フィールドの未指定）で代表させており、それとは独立した「必須パラメータ自体の欠落」というケースを別途テストする必要があることを見落とした。

### 教訓

バリデーション異常系は以下を区別して設計する。
- **必須パラメータの欠落**：パラメータ自体が存在しない → HTTP 422
- **任意パラメータの未指定**：必須パラメータは存在するが任意フィールドがすべて空 → ビジネスロジックの HTTP 422

両者は通過するバリデーション層が異なるため、それぞれ独立したテストケースが必要。
