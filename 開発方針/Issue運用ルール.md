# Issue運用ルール

## タイトル形式

```
【工程】作業内容【操作】
```

### 工程の種類

| 工程 | 用途 |
|---|---|
| `【要件定義】` | 要件定義書の作成・修正 |
| `【設計】` | 設計書・レビュー指摘表の作成・修正 |
| `【実装】` | コードの追加・修正 |
| `【テスト】` | テストコードの作成・修正 |
| `【その他】` | 環境設定・開発方針など上記に当てはまらない作業 |

### 操作の種類

| 操作 | 用途 |
|---|---|
| `【作成】` | 新規ファイル・機能の作成 |
| `【追加】` | 既存ファイル・機能への追加 |
| `【修正】` | 誤り・不備の修正 |
| `【レビュー】` | 設計書・コードへのレビュー指摘 |
| `【確認】` | レビュー指摘対応の再鑑・確認 |

### タイトル例

```
【要件定義】要件定義書の格納【作成】
【設計】レビュー指摘表の格納【作成】
【設計】レビュー指摘対応（CLUD/ユーザー操作）【修正】
【実装】全ユーザー情報取得【作成】
【その他】設計書記載方針追加【追加】
```

---

## 概要テンプレート

```markdown
## 作業スコープ
- 対象ファイル・機能を記載

## 完了条件
- [ ] 完了したらクローズする条件を記載

## 関連（任意）
- 指摘No.番号 / 関連Issue番号など
```

### 記載例（レビュー指摘対応）

```markdown
## 作業スコープ
- 設計書/CLUD/ユーザー操作 配下の指摘対応

## 完了条件
- [ ] 指摘No.1 ユーザー作成 対応完了
- [ ] 指摘No.1 ユーザー情報削除 対応完了
- [ ] 指摘No.2 ユーザー情報削除 対応完了
- [ ] 指摘No.3 ユーザー情報削除 対応完了
- [ ] 指摘No.1 ユーザー情報取得 対応完了
- [ ] 指摘No.1 ユーザー情報更新 対応完了
- [ ] 指摘No.2 ユーザー情報更新 対応完了
- [ ] 指摘No.1 全ユーザー情報取得 対応完了
- [ ] 指摘No.2 全ユーザー情報取得 対応完了

## 関連
- なし
```

### 記載例（設計書作成）

```markdown
## 作業スコープ
- 設計書/CLUD/ユーザー操作 配下の設計書を格納

## 完了条件
- [ ] ユーザー作成 設計書作成完了
- [ ] ユーザー情報取得 設計書作成完了
- [ ] ユーザー情報更新 設計書作成完了
- [ ] ユーザー情報削除 設計書作成完了
- [ ] 全ユーザー情報取得 設計書作成完了

## 関連
- なし
```

## PRのタイトルと概要

IssueとPRは1:1対応のため、PRタイトルはIssueタイトルをそのまま使用する。

### タイトル

```
【設計】レビュー指摘対応（CLUD/ユーザー操作）【修正】
```

### 概要

```markdown
Closes #○○
```

`Closes #○○` を記載することでマージ時にIssueが自動クローズされる。

---

## コミットとの紐付け

IssueはPRと1対1で対応させ、PRには関連するコミットをまとめる。  
詳細は [コミット運用ルール](コミット運用ルール.md) を参照。

```
Issue（完了条件のチェックボックス）
  └── branch: feature/XX
        ├── commit: [fix] ユーザー作成 指摘No.1 ...
        ├── commit: [fix] ユーザー情報削除 指摘No.1 ...
        └── commit: [fix] ユーザー情報削除 指摘No.2 ...
  └── PR → merge → Issueクローズ
```
