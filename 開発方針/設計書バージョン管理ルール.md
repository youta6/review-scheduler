# 設計書バージョン管理ルール

## バージョン表記

ファイル名にバージョンを付与する。

```
設計書名_vX.Y.md
```

---

## バージョンの意味

### v1.0 到達前

| バージョン | 状態 |
|---|---|
| `v0.1` | 初版（レビュー・指摘対応中） |
| `v1.0` | 再鑑完了（承認済み） |

- `v0.1` から `v1.0` への更新は**再鑑完了時のみ**行う
- 指摘対応中の中間状態はgit履歴で管理し、ファイルのバージョンは上げない

### v1.0 到達後

| バージョン | 用途 | 例 |
|---|---|---|
| **メジャー（X.0）** | 仕様の根本的な変更・設計の大幅な見直し | v1.0 → v2.0 |
| **マイナー（1.X）** | 仕様追加・誤記修正を含む軽微な変更 | v1.0 → v1.1 |

---

## バージョンアップのタイミング

| タイミング | バージョン操作 |
|---|---|
| 再鑑完了 | `v0.1` → `v1.0` |
| 仕様追加・軽微な修正 | `v1.0` → `v1.1` |
| 仕様の根本的な変更 | `v1.X` → `v2.0` |

---

## ファイルリネームとgit

バージョンアップ時はファイルをリネームする。  
履歴を追跡するため `git log` には `--follow` を付けること。

```bash
git log --follow --oneline <ファイルパス>
```
